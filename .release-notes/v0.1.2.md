# v0.1.2 — Kenning Continuity

The command line introduced the product by its former name.

```
$ kenning-continuity --help
Temporal Knowledge Substrate MCP Server     ← before
Kenning Continuity — an MCP server for domain-scoped enterprise knowledge
```

One string, in the argparse description. Nothing else had survived the rename —
the MCP server already registered as `kenning-continuity` and the startup log
already said Kenning Continuity — but this was the first line a person saw from
the CLI, on the first release carrying the name, so it was the wrong line to
leave standing.

It is fixed rather than amended into v0.1.1 because a published tag is a
promise about a commit. Moving one to correct a mistake costs more than the
mistake: it makes every ref in the repository a thing that has to be checked
rather than trusted. v0.1.1 remains exactly as sealed, and is simply a release
that never reached the package index.

This is the first release published to PyPI.

## Also in this release

`.pii-allow` — a per-repository allowlist for the release PII gate's new
name-shape check. Each entry pins an exact string and requires a reason, so the
file records rulings rather than silencing a pattern; a line without a reason is
refused. Every entry in it is a tool title, a licence phrase or a heading that
merely looks like a personal name.

It is excluded from the built sdist and wheel. The artifact carries what you
need to *use* the work; `.pii-allow` is used to *gate* the work, and is read
only by tooling nobody installing this package has. It stays in the repository,
where a ruling belongs.

It is here because the gate that guards these releases was found to have been
enumerative in the person dimension — it could only recognise people someone had
already listed. It now also recognises name *shape*, which is what catches the
person nobody thought to list.

## Unchanged in this release

The ontology is untouched, so the model stays at
`docs/design/ontology/v0.1.1.tql`. A version-stamped model names a distinct
artifact and earns a new number when the artifact changes — not when the
package around it does. `list_knowledge_types` and `list_connection_types`
remain the live authority either way, and `HOWTO.xml` still carries no version
at all.

Everything else is as described in
[v0.1.1](https://github.com/kenningai/kenning-continuity/releases/tag/v0.1.1).

## Requires

Python 3.10+ and a Neo4j 5.x instance. `pip install kenning-continuity`.
