# v0.2.1 — Kenning Continuity

The read tools now return the provenance the write tools record. Nothing about
how knowledge is written changes, and no existing field is removed or renamed.

## Provenance in every read

`create_knowledge` and `evolve_knowledge` record `basis` (on the `DISCOVERED`
edge) and `sources` (on the node). Before this release no read tool returned
either, so a reader checking provenance through the tools would find none,
even where it had been recorded. If you audited provenance that way, audit it
again.

- `get_domain_state` and `search_knowledge` now return each entity's `basis`
  and `sources`.
- `get_chain_history` now returns `sources` on every version, and `basis` on
  each `discovered_by` entry, because basis is a fact about the occasion that
  wrote the version.

## Provenance belongs to a version

`basis` and `sources` are read from the version itself and are never
inherited. A revision cites what it drew on; the claims it carries forward
stay cited on the version that first made them, which `get_chain_history`
shows. A revision that recorded no sources reads as `null`, not as its
predecessor's sources, because showing those would claim the revision drew on
something it never cited.

`null` means nothing was recorded. On a graph that predates these fields, most
entities will read `null`. That is not evidence that the knowledge is
unsourced, and the tool descriptions say so. The key is always sent, never
dropped.

A version reached by more than one `DISCOVERED` edge (possible on graphs that
used `merge_knowledge`, removed in v0.2.0) whose edges disagree on `basis`
reads as `null` in `get_domain_state` and `search_knowledge`.
`get_chain_history` lists each edge's `basis`.

## What `sources` asks for

The description of `sources` now says what the field is for. Cite what was
actually consulted. Cite the original, not a copy of it: the channel a
transcript was exported from, not the transcript. Never compose a plausible
source. `basis` says how something arrived; `sources` says from what.

## Verified

- Unit: 85 passed.
- Integration, against Neo4j: 120 passed, including the new
  `tests/integration/test_provenance.py` (11 tests). The suite was shown to
  fail in both directions. Against the v0.2.0 read code, the six tests that
  expect recorded provenance fail. Against a read that inherits provenance
  down the chain and picks one of two conflicting bases, three tests fail.
  Against a read that fills a missing `basis` with a plausible default, five
  fail. Each of the 11 tests fails against at least one of these.
- pyright: clean.
